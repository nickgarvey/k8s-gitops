# Agent Guidelines

## Destructive Actions

**CRITICAL: ALWAYS ask the user before performing any destructive action.**

### What Counts as Destructive

**ANY file deletion**, including but not limited to:
- Files in the workspace (even if they appear temporary or test-related)
- Files in `/tmp` or other temporary directories
- Files created by the agent during the current session
- Backup files, log files, or any other files
- **When in doubt, ASK - never assume cleanup is safe**

**Kubernetes resource deletion:**
- Deleting PVCs, PVs, or any persistent data
- Deleting deployments, pods, services, or any Kubernetes resources
- Cluster resets or etcd operations
- Rebooting nodes

### Rules

1. **Never delete files without explicit user permission** - even if you created them, even if they're in `/tmp`, even if they appear to be temporary
2. **Never delete Kubernetes resources without explicit user permission**
3. **When in doubt, ask first** - it's better to ask than to delete something important
4. **The user decides what is safe to delete** - not the agent

### Examples

❌ **DON'T:** `rm -f /tmp/secret-temp.yaml` (even if you created it)  
✅ **DO:** Ask: "Should I clean up the temporary files I created in /tmp?"

❌ **DON'T:** Delete a pod because it appears to be in an error state  
✅ **DO:** Ask: "I see pod X is in an error state. Would you like me to delete and recreate it?"

This applies regardless of whether data appears to be "test data", "fresh", "temporary", or "unimportant". The user decides what is safe to delete.

# Network Configuration

The cluster is **IPv6-only** (`enable-ipv4: "false"` in `vendor/cilium/cilium.yaml`).
Pods, Services and LoadBalancers have IPv6 addresses only; IPv4 exists on the LAN and for
the nodes' host addresses, not inside the cluster.

Those addresses are a routed Hurricane Electric `/48`, so they are **globally routable
GUAs, not ULAs**. Inbound `he-ipv6 → LAN` is default-deny at the router, so exposure is
opt-in per address — but an address being "internal" does not make it private.

## Where the network facts live

`~/nix-configs` is the source of truth. Read them there rather than copying them here,
where they drift:

| What | File |
|------|------|
| Subnet plan for `2001:470:482f::/48`, node IPs/MACs, pod CIDRs | `modules/networking/lan-hosts.nix` |
| LAN CIDR, router interfaces | `modules/router/default.nix` |
| DHCP pool and reservations | `modules/router/kea-dhcp.nix` |
| Cluster/Service CIDR, API TLS SANs, registry mirror | `modules/k3s/k3s-common.nix` |
| Firewall, WAN port forwards | `modules/router/nftables.nix` |
| Authoritative DNS, resolver, public DNS front door | `modules/containers/knot-auth.nix`, `modules/router/knot-resolver.nix`, `modules/containers/public-dns-proxy.nix` |

## LoadBalancers — Cilium LB-IPAM, not MetalLB

There is no MetalLB. Cilium allocates from the IPv6 pool in
`manifests/cilium/l2-config.yaml` and announces via L2. Pin an address with the
`io.cilium/lb-ipam-ips` annotation plus `ipFamilies: [IPv6]` /
`ipFamilyPolicy: SingleStack`.

Before picking one, list what is already taken:

```bash
grep -rh lb-ipam-ips manifests/*/*.yaml | sed 's/.*: //' | tr -d '"' | sort
```

# DNS

Names come from three places:

1. **`*.k8s.home.garvey.sh`** — auto-generated by `k8s_gateway`
   (`manifests/k8s-gateway/`) from every LoadBalancer Service, as
   `<svc>.<ns>.k8s.home.garvey.sh`. Also still serves the legacy `k8s.home.arpa`.
2. **`*.bigeye-turtle.ts.net`** — Tailscale Ingress (`ingressClassName: tailscale`),
   tailnet-only, TLS terminated by Tailscale. The default for HTTP UIs.
3. **`*.garvey.sh`** — public names with real Let's Encrypt certs. Only `oci.garvey.sh`
   today. See `manifests/acme-dns/ONBOARDING.md`.

## ⚠️ LoadBalancer Services are publicly enumerable

`home.garvey.sh` is **publicly delegated** from Cloudflare to a self-hosted Knot server on
the router, which in turn delegates `k8s.home.garvey.sh` to `k8s_gateway`. The full chain
resolves from the open internet:

```
. → sh → garvey.sh (Cloudflare) → home.garvey.sh (Knot) → k8s.home.garvey.sh (k8s_gateway)
```

So **creating a LoadBalancer Service publishes its name and GUA to anyone who asks.**
Resolvable is not the same as reachable — inbound IPv6 is still default-deny at the
router — but do not treat an address as secret because it is "internal".

# Container Registry (zot)

Registry: `oci.garvey.sh` (TLS, Let's Encrypt prod cert)

## Quick Commands

List all repositories:
```bash
curl -s https://oci.garvey.sh/v2/_catalog | jq
```

List tags (requires skopeo from nix environment):
```bash
nix develop --command skopeo list-tags docker://oci.garvey.sh/<repo>
```

Pull with podman:
```bash
podman pull oci.garvey.sh/<repo>:<tag>
```

Push with podman:
```bash
podman tag <image>:<tag> oci.garvey.sh/<repo>:<tag>
podman push oci.garvey.sh/<repo>:<tag>
```
